🧩 GenUI Studio
Repository: GenUi
A generative UI playground using a bounded implementation of Google's A2UI protocol and Adobe React Spectrum. It explores how an equipment-rental request can become an interactive discovery, comparison, or enquiry experience.
The repository documents component catalogs, schema validation, data binding, local state, and a design-system adapter boundary. A credential-free demo makes the main flows accessible; an optional Gemini development integration provides a separate model-backed path.
Why I find it interesting: it brings together interface architecture, agent output, and the controls needed to render structured responses safely.
Independent example using fictional equipment data. Additional design-system adapters are extension plans, not completed integrations.

🪐 Self Astrologer
Repository: self-astrologer
A browser-based astrology exploration and learning project combining chart calculations, interactive 2D and 3D planetary views, transit exploration, educational content, and personal reflection tools.
The current implementation uses Swiss Ephemeris through WebAssembly and includes local journaling, chart exports, and browser video export. Its interpretations are authored and rule based; a secure AI backend is part of the planned next layer.
Why I find it interesting: it brings computational detail, visual interaction, and guided learning into one experience. The product direction emphasizes curiosity and self-reflection.
🔬 NeuroResearch Agent
Repository: Agentic-Lib
An application project for discovering, organizing, ranking, and summarizing research across neuroscience, neurotechnology, and related fields.
Its documented architecture combines a Python/FastAPI backend with a Next.js frontend, source-ingestion adapters, normalized paper records, and briefing generation.
Why I find it interesting: useful research tools need careful information handling—from source collection and deduplication to a readable final summary.
🧠 Affective Belief Persistence
Repository: affective-belief-persistence
A research framework investigating how memory, prior interactions, and changing evidence affect the observable behavior of language-model agents.
The project includes deterministic simulations, evaluation infrastructure, reproducible artifacts, and explicit execution gates. Its current work establishes an offline experimental foundation; live behavioral findings have not been established.
Why I find it interesting: it turns questions about agent behavior into questions we can define, test, and evaluate carefully. The research concerns observable behavior, without claiming that models experience human emotions.

How I approach system design
I like to understand how an experience works from end to end: what the user needs, where state lives, how components communicate, what happens when something fails, and how the team will maintain it.
The questions I return to include:
- Boundaries: what belongs in a shared platform, an application, a service, or an adapter?
- Contracts: how can schemas, APIs, and component interfaces make collaboration clearer?
- State: what should be local, persistent, shared, or recoverable?
- Reliability: how should validation, failure handling, retries, and observability support the user journey?
- Performance: where do rendering, payload size, network calls, and caching affect the experience?
- Trust: how should authentication, authorization, privacy, and AI execution limits influence the design?
- Evolution: what is the smallest useful version, and what needs to stay replaceable?
I use prototypes, technical specifications, architecture decisions, and tests to make those trade-offs concrete. I want the implementation to teach me something about the design.
